# Papyrus - Development Guide

## Project Overview
Papyrus is a web-based print and scan server for network-connected Brother DCP-L2540DW (and potentially other devices). It provides a responsive web UI for managing print jobs (hold-release with optional PIN, reprint), scanning (with OCR, profiles, PDF collation, image enhancement, deskew, and template naming), copying, SMB share integration, bidirectional email (send + webhook receive), bidirectional cloud storage (Google Drive/Dropbox/OneDrive/Nextcloud via OAuth2 or WebDAV), FTP/SFTP upload, Paperless-ngx archival, outgoing webhooks, audit logging, usage dashboard, backup/restore, retention policies, and PWA support.

## Tech Stack
- **Backend**: Python 3.15, FastAPI, Uvicorn, SQLAlchemy async (asyncpg), Alembic
- **Frontend**: React 19, Vite, TypeScript (strict, `verbatimModuleSyntax`), Tailwind CSS, TanStack Query v5 (server state), Zustand (client state), React Router v6, vitest + Testing Library + msw (unit tests). Design system (see `frontend/src/index.css` `@theme`): "paper" = remapped gray-* scale + "ink" accent scale (use `ink-*`, never `blue-*`); IBM Plex Sans/Mono via @fontsource with mono reserved for data readouts (IDs, timestamps, sizes, URLs/IPs/device strings); `rule-perf` (perforation divider) and `led` (status dot) utilities; Skeleton/EmptyState/ErrorState primitives in `components/common/`; lucide-react icons
- **Database**: PostgreSQL 16
- **Printing**: CUPS (driverless/IPP Everywhere), AirPrint via Avahi mDNS, pycups
- **Scanning**: `scanimage` subprocess (SANE/sane-airscan) or the native Brother network client (`brothernet:<host>` devices), eSCL server for network scanning
- **Network Discovery**: Avahi mDNS (AirPrint `_ipp._tcp`, eSCL `_uscan._tcp`); python-zeroconf for admin-triggered printer discovery scans (`_ipp`/`_ipps`/`_printer._tcp`) since avahi-browse/CUPS dnssd need D-Bus, unavailable in-container
- **Doc Conversion**: LibreOffice headless (DOCX/ODT/XLSX/PPTX → PDF)
- **OCR**: Tesseract + ocrmypdf for searchable PDFs
- **Auth**: OIDC (Authentik/Keycloak) via authlib + admin-generated API tokens + group-based role mapping
- **SMB**: pysmb for network share browsing/read/write
- **WebDAV**: httpx-based WebDAV client for Nextcloud and other WebDAV servers
- **FTP/SFTP**: stdlib ftplib + optional paramiko for file uploads
- **Image Processing**: Pillow + numpy for brightness/contrast/rotation/crop/deskew
- **PWA**: vite-plugin-pwa with workbox service worker
- **Deploy**: Docker multi-stage build, amd64 and arm64 (release.yml builds each natively and merges digests into one manifest; the arm64 image has no brscan4, so `brother4:` devices need amd64 and ARM hosts use `brothernet:`; ci.yml's `arm64` job builds the image, runs the suite and checks `/health` on `ubuntu-24.04-arm`); (`network_mode: host` for mDNS) behind Traefik

## Project Structure
- `backend/app/` — FastAPI application
  - `main.py` — App factory, lifespan, middleware
  - `config.py` — Infrastructure-only Pydantic Settings (`PAPYRUS_` env prefix); UI-managed settings are in AppConfig DB
  - `auth/` — OIDC + API token auth; `auth/ws.py`'s `authenticate_websocket(ws, db)` resolves a WebSocket handshake's identity (Bearer header, `?token=` query param, or session cookie — same resolution order as the HTTP path) and enforces a same-origin check first (WebSocket isn't subject to CORS, so a browser-sent `Origin` header's host must match `Host`)
  - `routers/` — API route handlers
  - `services/` — Business logic (CUPS — `cups_service.get_default_release_queue_name(db)` resolves the default printer's `{cups_name}_release` queue, the single target every release/cancel/delete path uses, raising `PrinterUnavailableError` when there's no default; `throttle.py`'s `Throttle(max_failures, lockout_seconds)` is an in-memory brute-force lockout (`TooManyAttemptsError`) keyed per login attempt (`ip:username`) and per release-PIN guess (`pin:{job_id}`); `file_locks.py`'s `lock_for(path)` hands back a per-path `asyncio.Lock` so OCR and in-place image rewrites on the same scan file never race; `net_guard.py`'s `assert_safe_host(host)` is a shared SSRF guard rejecting loopback/link-local/multicast/unspecified addresses for outbound admin-triggered connections (WebDAV, etc.) — scanning, SMB, email, cloud, Paperless-ngx, OCR, audit, WebDAV, FTP, image enhancement, webhooks, retention, `thumbnail_service.py` for cached scan previews, `settings_cache.py` for a 30s in-process TTL cache in front of `get_setting`, `http_client.py` for a shared pooled `httpx.AsyncClient`, `discovery_service.py` for zeroconf mDNS printer discovery, `ipp_client.py` for a minimal hand-rolled IPP Get-Printer-Attributes client (probe/discover enrichment, reused by supply alerts), `test_page_service.py` for printer identify-sheet test pages, `duplex_service.py` for two-pass duplex (`merge_backs_atomic(front, back, out, rotate_backs, skip_blank_backs=False, reverse_backs=True)` interleaves via pypdf into a NEW file — temp file, fronts' mode via fchmod, fsync file+dir, `os.replace`; optional `/Rotate` 180 on backs; `is_blank_image` drops a back only when bright flat paper with ~no marks outside a 3% margin, constants at the top; `POST /api/v1/scans/{id}/backs` (owner/admin or 404; completed ADF PDF, not `duplex_merged`) runs `scan_batch` on the row's scanner/resolution/mode, then adds a merged `ScanJob` (`duplex_merged=true`) and keeps the backs as their own row, sets `duplex_merged` on the fronts row (migration 015) so neither merges again, broadcasts `scan_completed` per row, and runs audit/webhook/`run_post_scan_actions` for the merged row; on count mismatch (409 `BacksMismatchError`) or merge failure only the backs row is added; frontend `ScanBacksDialog` from HistoryRow and ScanForm, gated by `lib/scanBacks.ts`), `paper_service.py` for the default printer's loaded paper (`get_loaded_paper(uri)` — handles `ipps` via HTTPS, IPv6 hosts, malformed URIs → None; → `A4`/`Letter`/`Legal`/None from IPP `media-ready` then `media-default`, 3s overall bound, 60s cache incl. failures; served by `GET /api/v1/printers/default/paper` as `{media}`; frontend `usePaperChoice(allowed)` falls back to A4 and never overwrites a user pick), `alert_service.py` for supply/error alerts — `check_alerts(db)` polled by `main._alert_loop`, with False→True hysteresis persisted in the internal `alert_state` AppConfig JSON row (a CUPS listing failure is logged and leaves that state untouched rather than clearing it) and fan-out to `printer.supply_low`/`printer.error` webhooks + `alert_email`; CUPS and IPP marker readings for the same cartridge are merged by normalized name before threshold checks so one physical supply never double-reports)
  - Scanning backends (`services/scan_service.py`): `ScanService` owns the lock, SSRF guard (`net_guard.assert_safe_host`, native devices only), format conversion, ADF merge and cleanup; a `ScanBackend` (`acquire_page`/`acquire_batch`/`probe`/`options(device)`) does the device I/O, picked by `_backend_for(device)`. `SaneBackend` is `scanimage`; `BrotherNetBackend` handles `brothernet:<host>` (host validated by `parse_native_device`, malformed → `ScanRequestError`) via `brother_client.BrotherScanClient` over `brother_protocol` (TCP 54921, DCP-L2540DW only). It maps Color/Gray/Lineart to CGRAY/GRAY64/TEXT, offers 100/150/200/300/400/600 dpi, ignores a scan region for the feeder, and its `acquire_page` refuses an explicit feeder request: one `ESC X` always pulls every sheet and hanging up doesn't stop it (it can jam the printer). **On this printer paper in the feeder takes over a glass request** (hardware-verified: a full-page glass request with paper loaded feeds every sheet; a small-area one jammed), so a glass request is never refused and never sent with a partial area when either paper signal shows paper: `ScanService.scan` reads `FeederReading` first (`takes_over_glass`) and routes it as a feeder PDF (`_scan_feeder_pdf(glass_request=True)`); if the reading is unavailable, `BrotherScanClient.scan(source="flatbed")` decides at scan time from the handshake's own signals and returns pages marked `from_feeder`, which `acquire_page` hands back as a page list that `scan()` merges. The result is one PDF whatever `fmt` asked for, reported through `feeder_callback` (and `page_count_callback`); the web route then sets the row's `format=pdf`, `source=ADF`, `page_count`, and `ScanForm` shows the real source/format/pages (a note when they differ from the request). Copy prints the whole stack. A feeder request with an empty feeder stays a `ScanSourceError` 409. `ScanService.scan(source="ADF")` on a `feeder_takes_every_sheet` device (`brothernet:` and `brother4:`) therefore runs the batch path (`_scan_feeder_pdf`, shared with `scan_batch`, merging via `_merge_pages_to_pdf`), is PDF-only (other formats → `ScanRequestError` before any connection/scanimage), and reports the sheet count through `page_count_callback`; `options()` exposes `feeder_formats` and `ScanForm` restricts the format from it. Copy uses PDF for these feeders. eSCL ADF jobs on those devices asking for jpeg/png call `scan_feeder_pages`: pages are converted into a per-job `pages_<id>` dir under the scan dir and `NextDocument` serves them in order (served pages deleted, 404 when exhausted, `ScannerStatus` shows Processing with `ImagesCompleted`/`ImagesToTransfer` until the last is served); the dir is removed on DELETE, failure, cancellation and job expiry, and the `ScanJob` row stores the merged PDF (`format=pdf`, correct `page_count`). The client handshake treats a silent scanner as busy (10s per attempt, ~96s of retries, feeder reply included); probe reports busy after 3s. Cancellation is plain task cancellation in both backends (SANE kills the subprocess); there is no process-handle callback. A native glass scan drops its connection at once, but a native feeder stream can't be stopped, so on cancel or a client-side error the client keeps the connection and reads to the job-end marker, discarding data (`_drain_shielded`, shielded so repeated cancels don't cut it short), bounded per read by the 30s idle timeout; only then is the connection closed and the scan lock released. A device error frame, a read timeout/dropped connection or an unparseable stream ends it at once/quietly. A cancelling caller (eSCL DELETE) waits for that. Client errors (`ScanSourceError` 409, `ScanRequestError` 422, `ScannerBusyError`) propagate unchanged. `probe` for native is TCP connect + lease, never a scan, and busy counts as reachable (`busy: true`); `/status`, `/{id}/test`, `/diagnostics` (adds a `native` list) and `/health` use it. `discovery_service.discover_scanner_services` browses `_scanner._tcp`; `/api/v1/scanners/discover` appends port-54921 candidates confirmed by probe, with `driver: "brothernet"`, `supported` true only for `DCP-L2540DW` (others have `device: null`). Native Scanner rows carry no `brother_model`/`brother_ip`; `/register-brscan4` returns a 422 domain error when `brsaneconfig4` is missing (ARM).
  - `routers/device.py` — RFC 8628-style device grant under `/api/v1/auth/device` (`code`, `{user_code}` lookup, `approve`, `token`); table `device_authorizations` (migration 016, device code stored as sha256, `minted_token_id` lets a `device`-permission token revoke only tokens it minted via `DELETE /auth/tokens/{id}`; a token may also delete itself). New `device` permission (in `ALL_PERMISSIONS`); `get_current_user` now sets `request.state.token_id`. Poll errors are 400 `DeviceGrantError` with protocol `code`s; minted tokens are 15 min, owned by the approver. Module-level `RateLimiter`s (code 10/min, poll 60/min per token, lookup/approve 20/min per user). `GET /scans?mine=true` filters to the caller's scans; `POST /scans/{id}/cloud?folder_id=` (Drive id; path for Dropbox/OneDrive). Scan ownership (IDOR fix): `scanner.can_access_scan(user, request, job)` gates every by-id scan route (download, thumbnail, email, cloud, paperless, ocr, enhance, backs, smb, delete, WebDAV upload, progress WS; the `scans` WS channel too: `ws_manager.broadcast_scan(msg, owner_id)` filters sockets by their stored identity via `services/scan_access.py`, and an owner-less `scans` broadcast reaches nobody) and bulk-delete/collate/`list_scans` — owner, or admin (session, or token with `admin`); null-owner eSCL scans are visible to sessions only, never API tokens; inaccessible = 404 (ignored by bulk-delete). OIDC `/auth/login?next=` returns to a same-origin path after login.
  - `legacy_alias.py` — pure-ASGI middleware rewriting legacy `/api/*` (HTTP + WS) onto `/api/v1/*` from an ordered table (`TABLE`); all routers are mounted only under `/api/v1`. Permanent aliases (no Deprecation/Sunset): ingest, share-target, auth login/callback, cloud callback, email receive. OIDC/cloud redirect URIs and `webhook-info` still emit the legacy URLs on purpose (externally registered).
  - `models.py` — SQLAlchemy ORM models (`Printer.make_and_model`/`Printer.location`, nullable, populated via IPP probing — migration 013; migration 014 widens `file_size` on both job tables to BigInteger, adds `print_jobs.ingest_key` — a unique nullable idempotency key for network-ingest retries — partial unique indexes `ux_printers_default`/`ux_scanners_default` enforcing one default row per table, composite `audit_log` indexes for the admin filter UI, `ondelete="CASCADE"` on the `cloud_providers.user_id`/`smb_shares.created_by` FKs (a plain `ForeignKey(..., ondelete="CASCADE")` — there is no `passive_deletes` flag) so deleting a user with a connected cloud provider or SMB share no longer 500s, and widens `webhooks.secret` to Text because the secret is Fernet-encrypted at rest (`encrypt_value`/`decrypt_value_lenient`; legacy plaintext rows still verify))
  - `schemas/` — Pydantic models split into `common` (Page[T], ErrorResponse), `jobs`, `scans`, `admin`, `events` (webhook payloads + WS message models, included in the OpenAPI schema)
  - `api_docs.py` — OpenAPI tag metadata, `ErrorResponse`, `std_responses(...)`/`file_response`/`error_group` helpers, and `install_openapi` (422 error envelope, webhooks from `WEBHOOK_EVENTS`, WS models, 429 post-process); `/docs`, `/redoc`, `/openapi.json` are auth-gated unless the `public_api_docs` setting is on

HistoryPage's own pagination uses `queryKeys.jobs.history(page)`/`scans.history(page)` (`limit=50&offset=page*50`, "Load more") under the shared `jobs.historyAll`/`scans.historyAll` prefix, which `useRealtimeBridge` invalidates wholesale on the matching WS event rather than patching one page

  - `pages/` — Route pages, lazy-loaded (`React.lazy` + `Suspense`, see `AppShell`) and code-split per route

- `docs/api/` — hand-written API prose (README, webhooks, websockets, escl); the endpoint reference comes from the OpenAPI schema
- `docker/` — Dockerfile, compose.yaml, entrypoint, CUPS/SANE/Avahi configs
  - `entrypoint.sh` — starts avahi-daemon (skipped, and not supervised, when `PAPYRUS_DISABLE_MDNS` is set) and cupsd as foregrounded, backgrounded children (not `--daemonize`/exec'd, so this shell holds their real PIDs), generates a random `PAPYRUS_INGEST_TOKEN` per container start and writes it to `/run/papyrus/ingest.token` (mode 600; path overridable via `PAPYRUS_INGEST_TOKEN_FILE`, and the alembic cwd via `PAPYRUS_APP_DIR`, both for the test harness), polls `lpstat -r` (bounded, ~15s) until cupsd answers instead of a blind sleep, runs the Alembic migrations, then starts uvicorn the same backgrounded way. The shell then **supervises all three children** with a `wait -n -p` loop (bash ≥5.1): uvicorn exiting is the normal end-of-life path (its code becomes the container's), but cupsd or avahi-daemon exiting outside a shutdown logs `FATAL`, cleanly stops the survivors, and exits non-zero so compose's `restart: unless-stopped` recreates the container — previously a crashed cupsd/avahi left the web app running with printing dead ("printer is offline" on clients) until a manual bounce. A TERM/INT trap forwards the signal to all three children and waits for each to actually exit (`wait_for_pid`, polling `kill -0`) before this shell itself exits — `init: true` in compose.yaml makes this shell tini's only tracked child, so exiting early would let the kernel SIGKILL cupsd/avahi mid-shutdown instead of a clean stop. Regression-tested by `tests/test_entrypoint_script.py` (shims every daemon via PATH). `docs/troubleshooting.md` is the at-failure capture runbook for "printer offline" reports.
  - `cups/papyrus-backend` — Custom CUPS backend script for network print → hold queue. Posts the job to the ingest API with `curl`: text fields (title/username/etc., all untrusted from CUPS) go through **`--form-string`, never `-F`** — `-F` treats a value starting with `@`/`<` as read-from-file and `;` as a param separator, so a document title like `@notes` made curl abort with HTTP 000 and the job vanished; the file part uses a **fixed `filename=document.pdf`** (real title is preserved in the `title` field). Sends `X-Papyrus-Ingest-Token` (read fresh from `/run/papyrus/ingest.token` on every attempt, when the file exists) and a stable `ingest_key` (`boot_id:printer:job_id`, boot id from `/proc/sys/kernel/random/boot_id`) so a retried POST after a lost response is recognized as the same job instead of creating a duplicate held job; each attempt is bounded by `--connect-timeout 5 --max-time 300`. Retries on HTTP 000/5xx (~10× / 3s, rides through an API restart), does not retry 4xx, and on final failure `exit 1`s (`CUPS_BACKEND_FAILED`) so failures surface as failed jobs instead of silently completing — safe only because every Papyrus-created queue uses `printer-error-policy=abort-job` (aborts the one job, never disables the queue). Keeps the temp `.pdf` under `PAPYRUS_UPLOAD_DIR` for debugging. Regression-tested by `tests/test_cups_backend_script.py` (shims `curl`).
  - `avahi/airprint.service` — **static** AirPrint advert baked into `/etc/avahi/services/`; hardcodes `rp=printers/Papyrus`, so it needs a CUPS queue literally named `Papyrus`. That built-in zero-config hold queue is ensured on **every** startup by `cups_admin.ensure_default_queue()` (called unconditionally from `main._reconcile_on_startup` — lpadmin is create-or-modify, so this both creates it when missing (`printers.conf` isn't persisted across recreation) and re-enables + re-asserts `printer-error-policy=abort-job` on a queue cupsd left stopped, which a plain restart would otherwise carry over forever) with **no** second Avahi advert. Jobs to it are held and, having no matching `Printer` row, route to the **default printer** at ingest and release normally. The name `Papyrus` must stay in sync across `airprint.service`, `cups_admin.DEFAULT_QUEUE_NAME`, and `printers._SELF_ADVERTISEMENT_RESOURCE_MARKER`. Per-printer queues added via the UI get their own dynamic `{cups_name}.service` advert.
  - `avahi/` — Avahi mDNS daemon config + eSCL service advertisement

## Key Commands
```bash
# Backend development
cd backend && pip install -e ".[dev]"
uvicorn app.main:app --reload --port 8000

# Frontend development
cd frontend && npm install
npm run dev

# Database migrations
cd backend && alembic upgrade head
cd backend && alembic revision --autogenerate -m "description"

# Docker
docker compose -f docker/compose.yaml up --build
docker compose -f docker/compose.yaml down

# Tests (pytest runs -n auto by default; per-run per-worker DBs, dropped afterwards; --shard I/N splits files)
cd backend && pytest

# After ANY API change: regenerate the committed schema and TS types (CI drift-checks both)
cd backend && python -m app.openapi_export        # --check to verify
cd frontend && npm run gen:api
cd frontend && npm test

# Backend integration tests need a local test Postgres; they auto-skip
# (reason "test Postgres unreachable…") if it isn't running:
docker run -d --name papyrus-test-pg -e POSTGRES_USER=papyrus -e POSTGRES_PASSWORD=papyrus -e POSTGRES_DB=papyrus_test -p 127.0.0.1:5433:5432 postgres:16-alpine

# React Compiler experiment (default OFF; see vite.config.ts)
cd frontend && REACT_COMPILER=1 npm run build
```

The local backend venv doesn't have pycups (host lacks CUPS headers); `pip install -e ".[dev]"` still works and `backend/tests/conftest.py` stubs `sys.modules["cups"]` so tests import cleanly without it. Docker/CI images have real pycups. CI (`.github/workflows/ci.yml`) runs on every push/PR: 4 backend shards (ruff, `openapi_export --check`, pytest `--shard`) plus a `backend` aggregator check (the required check name), and a frontend job (eslint, `gen:api` drift check, `npm test`, build). `.github/workflows/release.yml` runs on every push to `main`: it requires the version in `backend/pyproject.toml`, `frontend/package.json`, and `backend/app/main.py` to match, and if tag `v<version>` doesn't exist yet it runs `ci.yml`, pushes the ghcr image (`:latest` + `:<version>`), creates the tag, and cuts the GitHub Release (a version bump merged to `main` is the release trigger). The backend job also runs a `postgres:16-alpine` service container (port 5433→5432, matching `PAPYRUS_TEST_DB_URL`'s default) so the ~52 integration tests execute in CI instead of skipping; a step after Pytest parses the `--junitxml` report and fails the job if any test was skipped, so a broken service container can't silently downgrade the suite. Because CI's image has real pycups (unlike local dev's stub), tests that would otherwise drive a live `cups.Connection` — alert polling, health checks, printer status watching — patch `cups.Connection`/`app.services.alert_service._cups_reachable` directly instead of relying on the import-time stub to no-op them.

## Environment Variables
Only infrastructure settings use env vars (`PAPYRUS_` prefix). All other settings are managed via the Settings UI and stored in the AppConfig database table.

**Infrastructure env vars** (see `backend/app/config.py`):
- `PAPYRUS_DB_URL` — PostgreSQL connection URL
- `PAPYRUS_ENCRYPTION_KEY` — Fernet key for encrypting secrets at rest
- `PAPYRUS_SESSION_SECRET` — Session cookie encryption key. `config.validate_runtime_secrets()` runs as the first statement in `main.lifespan`: a blank or placeholder (`change-me-in-production`) value raises `RuntimeError` and refuses to start, unless `PAPYRUS_DEV_MODE` is set, in which case it's only a warning
- `PAPYRUS_BASE_URL` — Public URL for OIDC callbacks and webhooks. Also drives the session cookie's `Secure` flag: `SessionMiddleware`'s `https_only` is `settings.base_url.lower().startswith("https://")` (`max_age` 14 days, `same_site="lax"`) — an `http://` base URL means a non-`Secure` cookie
- `PAPYRUS_OIDC_ISSUER`, `PAPYRUS_OIDC_CLIENT_ID`, `PAPYRUS_OIDC_CLIENT_SECRET` — OIDC provider
- `PAPYRUS_OIDC_SCOPES` — OIDC scopes (default: `openid email profile`)
- `PAPYRUS_OIDC_ADMIN_GROUP` — OIDC group name that grants admin role
- `PAPYRUS_OIDC_GROUPS_CLAIM` — Claim name containing group list (default: `groups`)
- `PAPYRUS_DEV_MODE` — Development mode (bypass OIDC)
- `PAPYRUS_DISABLE_MDNS` — Truthy (`1/true/yes/on/t/y`) stops Avahi advertising (AirPrint, eSCL, per-printer adverts); `cups_admin` skips writing/reloading `.service` files (stale ones are still removed). Default false
- `PAPYRUS_CORS_ORIGINS` — Comma-separated list of allowed CORS origins; empty (default) means same-origin only and `CORSMiddleware` isn't added at all, since the app is normally served from behind a reverse proxy on the same origin
- `PAPYRUS_INGEST_TOKEN` — Shared secret the network-ingest endpoint (`POST /api/v1/jobs/internal/ingest` (legacy path is a permanent alias)) requires in an `X-Papyrus-Ingest-Token` header; empty (default) means no token is required. The Docker image generates one per container start (`docker/entrypoint.sh`) and writes it to `/run/papyrus/ingest.token` for the CUPS backend script to read — not meant to be hand-set outside that flow
- `PAPYRUS_TEST_DB_URL` — Test-only: overrides the Postgres URL the test harness (`backend/tests/conftest.py`) targets (default `postgresql+asyncpg://papyrus:papyrus@localhost:5433/papyrus_test`); set by CI, or export it locally if your test Postgres runs somewhere other than the `papyrus-test-pg` one-liner above

**UI-managed settings** (stored in DB, configured via Settings page):
SMTP, cloud OAuth, scanner/printer config, OCR, FTP/SFTP, Paperless-ngx, retention, webhooks, OIDC group mapping, etc. Use `get_setting(db, key)` from `app.routers.settings` to read them in code. Supply/error alerts add: `alerts_enabled` (bool, default false), `alert_toner_threshold` (int percent, default 20 — markers strictly below this with a *known* level fire `supply_low`; unknown/absent levels never alert), `alert_email` (optional, onset-only — recovery notices are webhook-only), `alert_poll_minutes` (default 5, re-read every cycle by `main._alert_loop`). Hardening also added `smtp_security` (`starttls` | `tls` | `none`, default `starttls`), `sftp_host_key_fingerprint` (SHA256/base64 SFTP host-key pin; blank accepts-and-logs the fingerprint on first connect instead of refusing), and `audit_retention_days` (int, default 90 — 0 disables audit-log pruning). API settings (no env vars): `rate_limit_enabled`, `rate_limit_token_rpm`, `rate_limit_ip_rpm`, `public_api_docs` (default false), `trusted_proxies` (CIDR/IP list whose `X-Forwarded-For` the limiter honours). API section: `rate_limit_enabled`/`rate_limit_token_rpm`/`rate_limit_ip_rpm`, `public_api_docs`, and `trusted_proxies` (comma-separated IPs/CIDRs, validated on save, default `127.0.0.1/32,::1/128,172.16.0.0/12`; the rate limiter honours the rightmost `X-Forwarded-For` only from these peers). Never hold a DB transaction across slow I/O: `commit()` after reads and before scans, probes, SMTP, webhooks and post-scan deliveries.

**Webhook events** (`app/services/webhook_service.py`'s `WEBHOOK_EVENTS`): `print.release`, `print.delete`, `print.upload` (every job created through the upload helper — `POST /upload`, share-target, inbound email — held or auto-printed, `{id, title, user_id, source_type}`; network-ingest jobs fire only `print.held`, not this), `print.held` (a job lands in the hold queue — dispatched from the shared upload helper for both `POST /upload` and `POST /api/share-target`, and from network ingest when `auto_release` is off), `print.test_page`, `scan.complete`, `scan.delete`, `settings.update` (`{"keys": [...]}`, fired once per `PUT /api/v1/settings` call that actually changes a value), `printer.supply_low`, `printer.error` (also fired for offline/stopped printers) — the last two are alert_service's onset/resolved notifications.

## Development Rules
- **Commits**: Commit frequently as work progresses.
- **README.md**: Keep updated with any significant changes to setup, features, or architecture.
- **CLAUDE.md**: Keep updated with any changes to project structure, commands, or conventions.
- **Security**: Never use `shell=True` in subprocess calls. Always use argument lists. Validate file uploads server-side. Encrypt sensitive data at rest (Fernet).
- **Subprocess scanning**: Use `scanimage` with explicit argument lists, never string interpolation.
- **Database**: Use async SQLAlchemy with asyncpg. All migrations via Alembic.
- **Frontend**: TypeScript strict mode. Tailwind for styling. Server state lives in the TanStack Query cache, always keyed via the `queryKeys` factory in `api/queries.ts` (never an inline key array). Zustand is for client-only UI state (auth, theme, toasts, WS connection flags) — never server data. Realtime WebSocket events are applied to the Query cache exclusively through `useRealtimeBridge`'s `setQueryData` calls; components never open their own sockets for list data or refetch in response to an event.
- **Chart colors**: Dashboard charts (`components/dashboard/`) key color to series identity, never position — print is always `--chart-print` (process cyan), scan is always `--chart-scan` (process magenta), defined in `index.css` and flipped for dark mode there; never hardcode a hex in a chart component. HTML marks use `var(--chart-print|scan)` directly; SVG marks (Recharts `stroke`/`fill`) can't resolve `var()`, so they go through `useChartColors()` in `chartTheme.ts`, which re-reads the computed style whenever `<html>`'s `.dark` class flips.
- **Uploads**: Stream to disk (`save_upload_streaming`) rather than buffering whole files in memory; enforce `max_upload_size_mb` with an early 413 while streaming. The upload pipeline (validate mime type, stream-save, PIN handling, held/auto-print dispatch, `print.held` webhook) is factored into `_create_print_job_from_upload` in `app/routers/jobs.py`, shared by `POST /upload` and the PWA share-target route below rather than duplicated.
- **PWA share-target**: `POST /api/v1/jobs/share-target` (legacy `/api/share-target` is a permanent alias; `jobs.share_target_router` in `main.py`) is the manifest's `share_target` action; the OS share sheet navigates the browser there directly (Android/Chromium only), so it deliberately breaks the 401-JSON contract below — an unauthenticated request gets `RedirectResponse("/api/v1/auth/login", 303)` instead. It resolves the user by calling `get_current_user` directly and catching its `HTTPException` (not via `Depends`, so `app.dependency_overrides` doesn't reach it — tests authenticate with a real Bearer token instead), accepts one or more `file` form fields, runs each through the shared upload helper above, and redirects to `/print` (303) on success.
- **eSCL feeder handling** (`routers/escl.py`, `brothernet:` devices): `BrotherScanClient.feeder_reading` reads lease + `ESC D` (never `ESC X`, ~3s bound, None when busy/unreadable). `POST /eSCL/ScanJobs` returns 409 before creating a job only for Feeder with it empty (never for Platen: paper in the feeder takes over, a JPEG/PNG Platen job with paper becomes a held-pages job, a PDF one a single document; a late takeover on an unreadable printer turns the job into a PDF and updates the row); an unreadable printer falls through to the scan's own check. `ScannerStatus` adds `<scan:AdfState>` (`ScannerAdfLoaded`/`ScannerAdfEmpty`) from a 10s cache, never read while a scan/job is active, omitted when unknown; capabilities add `FeederCapacity` 35 (native and `brother4:`) and `AdfOption` `DetectPaperLoaded` (native only). A failed job returns 410 from `NextDocument` (503 only while scanning, 404 ends a normal job) and shows as `Aborted`/`AbortedBySystem` in `ScannerStatus`.
- **eSCL access**: `/eSCL/*` (`routers/escl.py`) has no auth of its own — real AirScan/Mopria/WSD-eSCL clients hit it with no credentials — so every route depends on `_require_lan_client`: the TCP peer must resolve to a private/loopback/link-local address, and only then (trusting the same-host reverse proxy) is `X-Forwarded-For`'s **rightmost** entry evaluated in its place; a non-LAN peer, or a non-LAN rightmost XFF entry, both 403. Fails closed on unparseable or missing input.
- **WebSocket events**: The `jobs`/`scans`/`printers` channels (`/api/v1/ws/jobs`, `/api/v1/ws/scans`, `/api/v1/ws/printers`; legacy `/api/system/ws/*` aliased) always broadcast the full serialized object (`job_created`/`job_updated`/`job_deleted`, `scan_completed`/`scan_deleted`, `printer_status`), never a partial payload — the frontend applies events incrementally instead of refetching. If a row is gone by the time a background task finishes, skip the broadcast rather than send a partial object.
- **Errors**: Raise domain errors from `app/exceptions.py` (`PapyrusError` subclasses — `NotFoundError` 404, `PrinterUnavailableError`/`ScannerBusyError` 503, `ExternalServiceError` 502, `UploadTooLargeError` 413) instead of `HTTPException`; their `detail` is sent to the client verbatim, so write it for end users and never put internal state, stack traces, or upstream error strings into it. Never do `HTTPException(500, str(e))` — let an unexpected `Exception` fall through to the catch-all handler in `register_exception_handlers`, which logs the traceback and returns a generic message instead.
- **Logging & request IDs**: All app and uvicorn logs flow through `app/logging_config.py`'s single stderr handler (JSON in prod, human-readable in dev) via stdlib `logging.config.dictConfig` — no structlog. `RequestIDMiddleware` (`app/middleware.py`) assigns/echoes an `X-Request-ID` header per request and stores it in the `request_id_var` contextvar (`app/request_context.py`); `get_request_id()` reads it from anywhere (including log filters) and every error JSON body includes the same id under `request_id`.
- **API contract**: new endpoints go only under `/api/v1` (routers mounted in `main.py`). Each needs a `summary`, a docstring, a `response_model` (or `file_response`/redirect/204), `responses=std_responses(...)`, and `Field(description=...)` on models; `tests/test_openapi_contract.py` enforces this (plus unique operationIds, webhook payload and WS model coverage). Errors use one envelope `{detail, code, request_id, errors}` (`errors` = 422 field locations/messages only). After any API change run `python -m app.openapi_export` and `npm run gen:api`; the frontend uses the generated types in `src/types/api.gen.ts`. A renamed/moved path needs an entry in `legacy_alias.TABLE`; only externally-registered URLs are permanent (`!`).
- **Status-code contract with the frontend**: 401 → the axios interceptor in `frontend/src/api/client.ts` calls `authStore.signOut()` (renders `LoginScreen` in place; no hard navigation), except for `/auth/me`, `/auth/local-login`, and `/auth/providers`, whose 401s are a normal, expected part of the login flow and must never trigger a sign-out; keep issuing 401 (never 403) for "not authenticated". 403 → authenticated but lacking the required role/permission (`require_admin`/`require_permission`); the frontend does not redirect on it, so don't reuse 401 for this case. 429 → rate limited, with `Retry-After`. 413 → upload exceeds `max_upload_size_mb`, raised as `UploadTooLargeError` mid-stream by `save_upload_streaming` before the whole body is buffered.
